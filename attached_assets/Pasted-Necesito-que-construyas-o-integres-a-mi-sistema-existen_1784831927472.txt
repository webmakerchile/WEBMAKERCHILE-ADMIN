Necesito que construyas (o integres a mi sistema existente de cotizaciones) un generador de cotizaciones en PDF que replique píxel a píxel el diseño del PDF adjunto (Cotizacion_MM_Moda.pdf). Ese PDF es la referencia visual absoluta: mismo layout, misma tipografía, mismos colores, mismos componentes. Lo único que cambia entre cotizaciones es el contenido, que será generado por un LLM (API de OpenAI/ChatGPT) a partir del contexto del cliente que yo le entregue.

0. Regla de arquitectura (NO NEGOCIABLE)

Esta es la regla más importante de todo el proyecto:

El LLM genera SOLO contenido en JSON (textos y precios netos). El LLM NUNCA genera HTML, CSS, ni realiza cálculos matemáticos.
La plantilla HTML/CSS es fija y está hardcodeada en el código. El JSON se inyecta en la plantilla.
Todos los cálculos financieros los hace el servidor en TypeScript: IVA, totales, suma del proyecto, división de pagos y formato de moneda. Jamás el LLM.
Si el JSON del LLM no pasa la validación, se reintenta automáticamente enviándole el error (máx. 2 reintentos).

Motivo: en versiones anteriores el LLM omitía el IVA, ponía mensualidades en $0 o dividía mal los pagos. Con esta separación, eso es matemáticamente imposible.

1. Stack y flujo
Backend Node/Express + TypeScript (integrar a mi app existente si ya está corriendo).
Render del PDF: plantilla HTML + CSS inyectada con los datos → Puppeteer → page.pdf({ format: 'A4', printBackground: true, margin: { top: 0, right: 0, bottom: 0, left: 0 } }).
Dato: el PDF original fue generado con WeasyPrint desde HTML/CSS, por lo que el diseño es 100% reproducible con CSS de impresión. Puppeteer logra el mismo resultado en Node.
Antes de generar el PDF, esperar document.fonts.ready para que las fuentes de Google Fonts estén cargadas.
Flujo del endpoint POST /api/cotizaciones/generar:
Recibe: { contexto_cliente: string, modulos_sugeridos?: string, precios_netos?: number[], mensualidad_neto?: number, esquema_pago?: [{porcentaje, momento}] } — contexto_cliente es texto libre: mi resumen de la reunión/conversación de WhatsApp con el cliente, con sus datos, números y dolores reales.
Llama al LLM con el system prompt de la sección 7 → obtiene JSON.
Valida con Zod (sección 6) + reglas de negocio. Si falla → reintenta con el error.
Calcula todos los montos con el módulo financiero (sección 5).
Renderiza la plantilla → Puppeteer → devuelve el PDF y lo guarda vinculado a la cotización en la base de datos.
Debe existir también una vista previa HTML en el navegador (misma plantilla, antes de exportar) y la opción de editar el JSON manualmente y re-renderizar.

5. Módulo financiero (TypeScript, en el servidor — el LLM jamás toca esto)
ts
const IVA_RATE = 0.19;

export const calcIva = (neto: number) => Math.round(neto * IVA_RATE);
export const calcTotal = (neto: number) => neto + calcIva(neto);

// Formato chileno: $2.499.000 (es-CL usa punto de miles, sin decimales)
export const clp = (n: number) => '$' + new Intl.NumberFormat('es-CL').format(n);

// División de pagos sobre el TOTAL CON IVA. El residuo por redondeo se asigna al último hito
// para que la suma de los hitos sea EXACTAMENTE el total.
export function splitPagos(totalConIva: number, esquema: { porcentaje: number; momento: string }[]) {
  const montos = esquema.map(h => Math.round(totalConIva * h.porcentaje / 100));
  const diff = totalConIva - montos.reduce((a, b) => a + b, 0);
  montos[montos.length - 1] += diff;
  return esquema.map((h, i) => ({ ...h, monto: montos[i] }));
}

Derivados que calcula el servidor y se inyectan a la plantilla: IVA y total de cada módulo, neto/IVA/total del proyecto (sumas de módulos), IVA y total de la mensualidad, y los montos de cada hito de pago. Ningún monto formateado viene del LLM.

Eres el redactor comercial de WebMaker Latam, agencia chilena de desarrollo web y software. Generas el CONTENIDO de cotizaciones comerciales en formato JSON. NO generas HTML, NO calculas IVA ni totales, NO formateas montos.

Recibirás el contexto real de un cliente (resumen de reuniones o conversaciones de WhatsApp) y opcionalmente la lista de módulos con sus precios netos. Con eso produces un único objeto JSON con el schema indicado.

REGLAS DE REDACCIÓN:
- Español chileno cercano y directo. Tuteo siempre. Cero jerga corporativa, cero tono robótico.
- portada.titulo: el BENEFICIO principal para este cliente en 4 a 8 palabras, en MAYÚSCULAS. No es el nombre del servicio, es lo que gana. Ejemplo: "TU CHATBOT, VENDIENDO LAS 24 HORAS". portada.titulo_resaltado es el fragmento final más potente (substring exacto del título).
- contexto.parrafos: párrafo 1 cuenta la historia del cliente CON SUS NÚMEROS REALES (años, clientes, volúmenes) reconociendo su mérito; párrafo 2 nombra el problema puntual con la estructura "El problema no es X — es Y".
- contexto.stats: 3 cifras. Las dos primeras son datos reales del negocio del cliente; la tercera es aspiracional del proyecto (ej: valor "0", descripción "horas del día sin respuesta, una vez tu chatbot esté funcionando").
- contexto.soluciones: 4 frases que parten con verbo en infinitivo o "Que…", concretas, mencionando detalles reales (nombre del sitio, canales, etc.).
- modulos: nombre corto y vendedor (ej: "Chatbot inteligente 24/7"); descripción de 1-2 frases centrada en el beneficio, no en la tecnología. El neto es el número entero exacto que te entregaron, sin IVA, sin puntos, sin formato.
- como_funciona.items: exactamente 6 cards. Los actores alternan entre el cliente final del negocio (CLIENTA, CLIENTE, PACIENTE… según el rubro), el dueño (TÚ) y AMBOS. Describen escenas del día a día, no features.
- pago.nota_personal: retoma UN detalle real de la conversación que humanice el cierre (ej: "Sabemos que esto lo estás conversando también con tu esposo — esta cotización queda a tu disposición para cuando decidan avanzar."). Si no hay ningún detalle así en el contexto, usa una frase cordial de disponibilidad sin inventar hechos.
- Si el contexto menciona demos, promesas o pedidos específicos del cliente, referéncialos ("igual que en la demo que vimos", "tal como lo pediste").

- Inventar cifras, nombres o hechos que no estén en el contexto entregado.
- Calcular o escribir montos con IVA, totales, o montos formateados con $ o puntos.
- Dejar precios en 0 o inventar precios si no te los entregaron: en ese caso usa el valor -1 en neto para que el sistema lo marque como pendiente.
